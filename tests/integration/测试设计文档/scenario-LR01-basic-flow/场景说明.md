# LR01 基本流程与 JSON 转换正确性

## 1. 场景背景与目的

`log-reader` 是 BFE 访问日志的消费端，负责：

1. 读取 BFE 输出的 protobuf 格式访问日志（b2log 格式）；
2. 根据配置选择需要输出的字段；
3. 将转换后的 JSON 消息发送到下游 Kafka。

本场景验证：

- `log-reader` 能正确读取并解析 b2log 日志；
- `mod_kafka` 能按 `kafka_config.data` 的字段配置输出 JSON；
- 输出 JSON 的字段、类型、值与输入 protobuf 日志一致；
- 不同 `FieldMode`（`require`/`default`/`all`/`customized`）的行为符合设计；
- 当日志条数超过 `MaxSizePerBatch` 时，`mod_kafka` 能将日志拆分为多个批次处理。

## 2. 运行模式

- **单组件模式**：仅启动真实 `log-reader` 进程。
- 不涉及真实 BFE 与真实 Kafka。

## 3. 涉及的 log-reader 配置文件

| 文件 | 说明 |
|------|------|
| `config.conf` | 服务基础配置，指定 pb 日志路径与加载模块 |
| `mod_kafka/mod_kafka.conf` | Kafka Broker、Topic、批次等配置 |
| `mod_kafka/kafka_config.data` | 输出字段配置 |

## 4. 配置设计

### 4.1 config.conf

```ini
[main]
httpPort=8992
httpAddr=127.0.0.1
maxCpus=2
monitorInterval=20

[PbAccessLogConf]
LogFile={{LOG_FILE}}
Modules=mod_kafka
MaxSizePerBatch=10
```

- `LogFile` 由测试框架替换为临时 pb 日志文件路径。
- `MaxSizePerBatch=10` 用于验证批次拆分。

### 4.2 mod_kafka.conf

```ini
[Basic]
DataPath = kafka_config.data
OpenDebug = true

[kafka]
Brokers = {{KAFKA_BROKER}}
Topic = bfe_ai_log
DeadLetterTopic = bfe_ai_log_dlq
Compression = none
BatchSize = 5
LingerMs = 100
MaxRetries = 1
```

- `Brokers` 由测试框架替换为 `MockKafka` 监听的本地地址。
- `BatchSize = 20` 与 `LingerMs = 100` 保证消息能及时发送到 Kafka。
- `MaxRetries = 1` 控制重试次数。

## 5. 测试例列表

| 编号 | 名称 | 核心验证点 |
|------|------|------------|
| TC-01 | 基本流程 | 写入 3 条日志，验证 Mock Kafka 收到 3 条 JSON 消息，字段值与输入 protobuf 一致，未配置字段不输出 |
| TC-02 | 批次拆分 | 写入 12 条日志（超过 MaxSizePerBatch=10），验证 12 条消息全部收到，且字段内容正确 |
| TC-03 | Customized 字段模式包含必需字段 | FieldMode=customized 且只配置一个字段时，验证必需字段仍被输出 |
| TC-04 | Default 字段模式 | FieldMode=default 时，验证默认字段集（92 个注册字段）被完整输出，且与 mod_log_mysql 写入列对齐 |
| TC-05 | All 字段模式 | FieldMode=all 时，验证所有注册字段（包括不常用字段）都被输出 |
| TC-06 | Require 字段模式 | FieldMode=require 时，验证仅输出 22 个必需字段 |
| TC-07 | JSON 结构稳定性 | 验证同一条消息多次解析结果一致 |
| TC-08 | optional 字段未设置输出 null | `ai_intent_confidence` / `ai_intent_latency_us` / `ai_intent_cache_hit` 未设置时输出 JSON null（与 MySQL NULL 未求值语义对齐），设置时输出原值 |
