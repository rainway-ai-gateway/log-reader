# log-reader 集成测试场景总体说明

## 1. 版本信息

| 项目 | 内容 |
|------|------|
| 版本号 | v1.1.0 |
| 对应实现 | `log-reader/tests/integration/implementation/` |
| 测试目标 | 验证 `log-reader` 读取 BFE protobuf 访问日志并向 Kafka（JSON 转发）或 MySQL 明细表（轻量报表形态）落库的完整链路 |
| 测试形态 | 仅启动真实 `log-reader` 进程；Kafka 用 `common.MockKafka`，MySQL 用外部实例（`LR_MYSQL_DSN`）或 testcontainers；不依赖真实 BFE |

## 2. 测试范围

本目录下的集成测试重点覆盖 `log-reader` 自身的日志消费与落库链路：

1. **日志读取链路**：`log-reader` 启动后监听 protobuf 访问日志文件，按 b2log 格式解析日志记录。
2. **配置消费链路**：`log-reader` 启动时加载 `config.conf`、`mod_kafka.conf`、`kafka_config.data`、`mod_log_mysql/mod_log_mysql.conf` 等配置文件。
3. **Kafka 转发链路**：将解析后的访问日志按字段配置转换为 JSON，通过 `mod_kafka` 发送到 Kafka。
4. **MySQL 落库链路（轻量形态）**：通过 `mod_log_mysql` 按固定 99 列映射批量幂等写入 `bfe_ai_request_log`，含列映射/零值规则/幂等重放/同秒并发不丢行/连接容错。

> 说明：本目录不验证 `bfe` 的 HTTP 转发行为，也不验证真实 Kafka 集群的持久化与消费；相关测试请参见 `bfe/tests/integration/` 与 Kafka 自身测试。

## 4. 公共前置条件

### 4.1 环境与组件前置条件

- 测试直接使用当前 `log-reader` 源码编译出的可执行文件（`go build`）。
- 编译产物缓存到 `log-reader/tests/integration/.integration-test-bin/`，同一次测试运行只编译一次。
- 每个测试例拥有独立的临时工作目录与随机监听端口。
- Mock Kafka 通过 `common.MockKafka` 启动，其地址在测试运行时动态写入 `mod_kafka.conf`。
- 测试日志通过 `common.LogGenerator` 直接写入 protobuf 访问日志文件，无需启动 BFE。

### 4.2 log-reader 前置条件

- `config.conf` 中配置 `PbAccessLogConf.LogFile` 指向测试生成的 pb 日志文件。
- `config.conf` 中启用被测模块（LR01/LR02：`mod_kafka`；LR03：`mod_log_mysql`；LR04：`mod_log_mysql`）。
- `config.conf` 中 `httpAddr = 127.0.0.1`，避免监听所有地址触发防火墙。
- `mod_kafka.conf` 中的 Kafka Broker 地址由测试框架根据 `MockKafka` 动态替换。
- `kafka_config.data` 静态定义需要输出的字段集合。

### 4.3 MySQL 前置条件（LR03 / LR04）

- MySQL 8.x（≥ 5.7.8，需 JSON 列）由二者之一提供：环境变量 `LR_MYSQL_DSN`（格式 `user:pass@tcp(host:port)/dbname`，凭据需具备 `CREATE/DROP DATABASE` 权限）或 testcontainers（需 Docker）；两者都不可用则用例 `t.Skip`。
- 测试自建随机名数据库并套用 `testdata/ddl/bfe_ai_request_log.sql` 内嵌副本（与 ai-gateway-api 权威 DDL 同步），结束即 DROP，**绝不使用 DSN 中自带的数据库名**。
- LR04 中依赖"暂停/恢复 MySQL 实例"的用例额外需要 Docker（`LR_MYSQL_DSN`-only 环境下跳过，其余用例照常执行）。

## 6. 运行方式

```bash
cd log-reader

# 运行本目录全部集成测试
go test ./tests/integration/... -v

# 运行单个场景
go test ./tests/integration/implementation/scenario-LR01-basic-flow/... -v

# 运行单个测试例
go test ./tests/integration/implementation/scenario-LR01-basic-flow/ -run TestLR01_BasicFlow -v

# MySQL 场景（LR03 / LR04）：指定外部实例；未设置且无 Docker 时用例 Skip
LR_MYSQL_DSN="root:****@tcp(127.0.0.1:3306)/" \
  go test ./tests/integration/implementation/scenario-LR03-mysql-write/... -v
```

## 7. 依赖与风险

| 风险点 | 说明 | 缓解措施 |
|--------|------|----------|
| 编译 log-reader 二进制耗时 | 每个 `go test` 进程首次需要编译 | 使用文件缓存，一次测试运行只编译一次 |
| 端口冲突 | 多个测试并发时可能争夺端口 | Mock Kafka 绑定 `127.0.0.1:0` 动态分配端口；log-reader monitor 固定端口但仅监听 `127.0.0.1` |
| log-reader 启动失败排查困难 | 配置错误可能导致启动失败 | 测试失败时打印 `log-reader.log` 与 `log-reader.wf.log` |
| 路径中的反斜杠导致 gcfg 解析失败 | Windows 路径含反斜杠会被当作转义符 | 配置生成器将路径转换为正斜杠 |
| Kafka 协议兼容性 | Mock Kafka 仅实现了 kafka-go Writer 所需的最小协议子集 | 随着测试需求扩展，逐步补充 ApiVersions/Metadata/Produce 的处理 |
| MySQL 不可用 | LR03/LR04 依赖真实 MySQL，CI 无 Docker 且未设 `LR_MYSQL_DSN` 时无法执行 | 用例 `t.Skip` 并打印启用方式；需要覆盖时在 CI 提供 DSN 或 Docker |
