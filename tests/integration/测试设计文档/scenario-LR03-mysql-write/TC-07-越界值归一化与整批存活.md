# TC-07 越界值归一化与整批存活

## 用例编号与名称

TC-07 越界值归一化与整批存活（`TestLR03_OutOfRangeValueSurvives`）

## 所属场景

LR03 MySQL 写入场景（scenario-LR03-mysql-write）

## 版本声明

- `log-reader`：含 issue #12 修复（`field_mapper.go` 写入前范围归一化 + `record_writer.go` 行级隔离）
- 依赖：`ai-gateway-api` 权威 DDL 中相关列为 `INT`/`SMALLINT`/`TINYINT`（本用例只读，不改 DDL）

## 测试目的

验证 proto `uint32` 超出 DDL 列类型的取值（`2147483648`、`4294967295`）**不再毒化整批写入**（issue #12，对应 SC2201-TC007 的 `A-09`/`A-10`）：

- `A-09`：越界值在进入 SQL 前被规范化（clamp 到列上限），不产生 MySQL 1264；
- `A-10`：同批正常行/401 鉴权拒绝行不得因单行异常丢失，`SEND_MYSQL_FAILED`/`MYSQL_CONN_LOST` 不增加。

修复前的失败形态：越界值原样写入 → `Error 1264 (22003)` → 同一语句退避重试 3 次无收敛 → `markDown` → 重连补写同错 → 整批（含正常行与 401 行）丢弃并计 `SEND_MYSQL_FAILED`、`MYSQL_CONN_LOST`。

## 运行模式

单组件模式：真实 `log-reader` 进程 + 真实 MySQL。本用例不重启进程。

## 前置条件

同 TC-01（MySQL 可用、专用测试库与表就绪、二进制已用最新源码编译）。

注意：集成测试缓存 `tests/integration/.integration-test-bin` 下的二进制，改动 `mod_log_mysql` 源码后需删除该缓存产物再运行，否则跑的是旧二进制。

## 配置构造

同 TC-01（`MaxSizePerBatch = 10`、写侧 `BatchSize = 5`）；监控端口由 `common.FreePort` 动态分配，用例轮询 `/monitor/mod_log_mysql` 读取计数器。

## 输入数据

6 条请求日志（`ai_requested_model` 互不相同；探针行与正常行/401 行同批写出）：

| 顺序 | logid | `proxy_delay_time` | 说明 |
|------|-------|--------------------|------|
| 1 | 93001 | 0 | 探针：范围下界，原样落库 |
| 2 | 93002 | 2147483647 | 探针：`INT` 上限边界，原样落库 |
| 3 | 93003 | 2147483648 | 探针：`INT` 上限 +1，应 clamp 到 2147483647 |
| 4 | 93004 | 4294967295 | 探针：`uint32` 上限，应 clamp 到 2147483647 |
| 5 | 93005 | 3 | 正常行（`proxy_delay_time = 3`） |
| 6 | 93006 | 3 | 401 鉴权拒绝行（`res_status_code = 401`） |

## 操作步骤

1. 准备环境并启动 `log-reader`（监控端口已固定）。
2. 依次写入 6 条日志（`-b` 读取，全部进入同一写批次窗口）。
3. 轮询等待表中出现 **6 行**（30s 超时）。
4. 断言行数 = 6。
5. 逐条查询探针行的 `proxy_delay_time`，断言等于上表"应落库值"。
6. 查询 `logid = 93005` 的 `proxy_delay_time = 3`、`logid = 93006` 的 `res_status_code = 401`。
7. 读取 `/monitor/mod_log_mysql`，断言 `VALUE_NORMALIZED = 2`、`SEND_MYSQL_FAILED = 0`、`MYSQL_CONN_LOST = 0`、`ROW_DROPPED_DATA = 0`。

## 预期结果

| 步骤 | 预期 |
|------|------|
| 3–4 | 行数 = 6——**修复前此处只有 1 行**（1264 毒化整批，仅下一批次的正常行落库，用例超时失败） |
| 5 | `93001 → 0`、`93002 → 2147483647`、`93003 → 2147483647`、`93004 → 2147483647`（clamp 到列上限，非 NULL、非丢弃） |
| 6 | 正常行与 401 行均在表中，取值正确 |
| 7 | `VALUE_NORMALIZED = 2`（两个越界字段值）、其余三个计数器均为 0 |

## 清理

停止 `log-reader` 进程，关闭数据库连接，DROP 测试专用数据库，删除临时目录。
