# TC-06 同秒并发不丢行

## 用例编号与名称

TC-06 同秒并发不丢行（`TestLR03_ConcurrentRowsSameSecondSurvive`）

## 所属场景

LR03 MySQL 写入场景（scenario-LR03-mysql-write）

## 版本声明

- `log-reader`：当前源码版本（含 `mod_log_mysql` 模块；本用例**不涉及本模块代码改动**）
- 依赖：`bfe` 侧 pb `logid` 逐请求唯一非 0（`bfe@89defa14`）+ `ai-gateway-api` 侧权威 DDL 把 `logid` 入键并收紧为 `NOT NULL DEFAULT 0`（`ai-gateway-api@64f278e`，issue bfenetworks/bfe#1417）

## 测试目的

验证明细表幂等键的**请求级判别能力**：同一秒内、同 `hostid` / 同 `ai_apikey_id` / 同 `ai_requested_model`，仅 `logid` 不同的并发请求必须**各自成行**。

修复前的失败形态：唯一键为四列 `(hostid, log_time, ai_apikey_id, ai_requested_model)`，其中 `log_time` 是秒级 `DATETIME`；写入侧 `ON DUPLICATE KEY UPDATE` 为**全列覆盖**，于是 n 个并发行只留 1 行——丢率恰为 (n−1)/n（生产实测窗口 13.5%），且被覆盖行的 tokens/cost 从求和中整体消失（聚合同样低估）。

## 运行模式

单组件模式：真实 `log-reader` 进程 + 真实 MySQL。本用例不重启进程。

## 前置条件

同 TC-01。表结构来自 `testdata/ddl/bfe_ai_request_log.sql` 内嵌副本——其 `uk_dedup` 与权威 DDL 一致：五列、含 `logid`，且 `logid` 为 `NOT NULL DEFAULT 0`。

## 配置构造

同 TC-01。

## 输入数据

- 2 条 `common.MakeRequestLog` 生成的请求日志：`logid = 91001` / `91002`，**同一** `ai_requested_model = same-second-model`。
- `MakeRequestLog` 对每次调用固定 `hostid`（由读取侧 `reader_util.GetHostId()` 注入）、`log_time`（`1782353290`）、`ai_apikey_id`（`key-id-123`），因此这 2 条日志共享**旧四列键的全部键值**——正是"同秒同 Key 同模型并发"的碰撞前提。
- 第 3 条：第 1 条的克隆（同 `logid = 91001`），仅 `ai_output_tokens` 改为 `777`（模拟同一请求重放且内容更新）。

## 操作步骤

1. 准备环境并启动 `log-reader`。
2. 依次写入第 1、2 条日志（不同 `logid`、同模型）。
3. 轮询等待表中出现 **2 行**（30s 超时）。
4. 断言行数 = 2；查询 `SELECT logid, ai_input_tokens ... ORDER BY logid`，断言两个 `logid` 都在结果中、`len(distinct logid) = 2`。
5. 写入第 3 条（同 `logid`、`ai_output_tokens = 777`），轮询等待 `logid = 91001` 行的 `ai_output_tokens` 变为 777。
6. 断言行数仍为 2（同一请求重放命中覆盖、不新增行）。

## 预期结果

| 步骤 | 预期 |
|------|------|
| 3–4 | 行数 = 2，两个 `logid`（91001/91002）各自成行——**修复前此处只有 1 行**（`row count = 1`，TC 超时失败） |
| 5–6 | 行数 = 2，`logid = 91001` 行的 `ai_output_tokens` 被覆盖为 777（无重复行） |

## 清理

停止 `log-reader` 进程，关闭数据库连接，DROP 测试专用数据库，删除临时目录。
