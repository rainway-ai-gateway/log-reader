# TC-01 基本写入全字段校验

## 用例编号与名称

TC-01 基本写入全字段校验（`TestLR03_BasicWrite`）

## 所属场景

LR03 MySQL 写入场景（scenario-LR03-mysql-write）

## 版本声明

- `log-reader`：当前源码版本（含 `mod_log_mysql` 模块）

## 测试目的

验证 `mod_log_mysql` 能把 protobuf 请求日志按 `field_mapper.go` 的 99 列清单正确写入 MySQL 明细表 `bfe_ai_request_log`：标量列取值正确、字符串零值落 NULL、布尔落 TINYINT、JSON 列内容与 pb 一致、API Key 标签按层级打平、`log_time` 与 pb `timestamp` 对应；同时断言 ai-cache/流量镜像/ai-intent 10 个新列（由 `MakeRequestLog` 填充）取值正确。

## 运行模式

单组件模式：真实 `log-reader` 进程（`Modules = mod_log_mysql`）+ 真实 MySQL（`LR_MYSQL_DSN` 外部实例或 testcontainers 容器）。不使用 MockKafka。

## 前置条件

1. MySQL 可用（`LR_MYSQL_DSN` 已设置，或本机 Docker 可启动 testcontainers），否则用例 Skip。
2. 测试专用数据库已创建，目标表已由 testdata 内嵌 DDL 副本（`testdata/ddl/bfe_ai_request_log.sql`）建好。
3. `log-reader` 二进制已编译；`mod_log_mysql.conf` 已注入真实连接参数（`BatchSize = 5`、`FlushIntervalMs = 200`）。

## 配置构造

- `config.conf`：`PbAccessLogConf.Modules = mod_log_mysql`，`MaxSizePerBatch = 10`，监控端口由 `{{HTTP_PORT}}` 占位（测试用 `common.FreePort` 动态分配，避免与其它场景或宿主机端口冲突）。
- `mod_log_mysql.conf`：`DBName` 指向测试专用数据库，`Table = bfe_ai_request_log`。

## 输入数据

3 条 `common.MakeRequestLog` 生成的请求日志（全字段非零确定性取值），`ai_requested_model` 互不相同以保证唯一键 `(hostid, log_time, ai_apikey_id, ai_requested_model, logid)` 互不冲突：

| 顺序 | logid | header_host | origin_uri | ai_requested_model | ai_target_model |
|------|-------|-------------|------------|--------------------|-----------------|
| 1 | 10001 | api.example.org | /v1/chat | gpt-4 | gpt-4-mapped |
| 2 | 10002 | api.example.org | /v1/chat | gpt-4o | gpt-4o-mapped |
| 3 | 10003 | other.example.org | /v1/embed | text-embedding-3 | text-embedding-3-mapped |

关键约定值：`err_code = ""`（字符串零值样例）、`err_msg = "ok"`、`is_trust_src_ip = true`、`ai_stream = true`、`ai_apikeytags` 仅 level1/level2 有值、`ai_input_tokens = 1000`、`ai_output_tokens = 200`、`ai_rate_limit_hits`/`ai_auth_reject_quota_plans`/`ai_auth_hit_quota_plans` 为非空结构、timestamp 固定 1782353290。

## 操作步骤

1. 准备 MySQL 测试环境（建库、应用 DDL）。
2. 生成临时配置并启动 `log-reader`（`-c`、`-l`、`-b`）。
3. 写入 3 条 b2log 记录。
4. 轮询等待表行数 ≥ 3（超时 20s，失败时 dump log-reader 日志）。
5. 按 `logid` 查询每行，逐列断言。

## 预期结果

- 表内恰好 3 行。
- 每行：`logid`/`product`/`log_tag`/`err_msg`/`header_host`/`ai_requested_model`/`ai_target_model`/`client_ip` 取值与输入一致。
- `err_code` 为 NULL（空字符串→NULL 的零值规则）。
- `is_trust_src_ip = 1`、`ai_stream = 1`（布尔→TINYINT）。
- `req_num = 1`、`ai_input_tokens = 1000`、`ai_output_tokens = 200`、`all_time = 11`、`backend_retry = 1`、`res_status_code = 200`。
- `req_headers`、`ai_rate_limit_hits`、`ai_auth_reject_quota_plans`、`ai_auth_hit_quota_plans` 四列 JSON 解析后与 pb 对应结构深比较一致。
- 标签打平：`level1Name = dep`、`level1 = ops`；`level3Name`/`level3` 为 NULL（未设置层级）。
- `log_time` 等于 timestamp 1782353290（UTC 比较）。

## 清理

停止 `log-reader` 进程，关闭数据库连接，DROP 测试专用数据库（或终止容器），删除临时目录。
