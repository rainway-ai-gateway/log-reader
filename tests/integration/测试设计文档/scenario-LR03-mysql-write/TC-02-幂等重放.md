# TC-02 幂等重放

## 用例编号与名称

TC-02 幂等重放（`TestLR03_IdempotentReplay`）

## 所属场景

LR03 MySQL 写入场景（scenario-LR03-mysql-write）

## 版本声明

- `log-reader`：当前源码版本（含 `mod_log_mysql` 模块）

## 测试目的

验证 `INSERT ... ON DUPLICATE KEY UPDATE` 幂等语义：同一唯一键 `(hostid, log_time, ai_apikey_id, ai_requested_model, logid)` 的日志重发或 `-b` 补读时，不产生重复行、冲突行值被覆盖——即 log-reader 重发、重启补读场景下数据不重复、最终值正确。注意：本用例的重放**使用同一 `logid`**（同一请求重放，应折叠为 1 行）；"不同 `logid` 的同秒并发请求各自成行"由 TC-06 覆盖。

## 运行模式

单组件模式：真实 `log-reader` 进程 + 真实 MySQL。用例中段会重启一次 log-reader。

## 前置条件

同 TC-01。

## 配置构造

同 TC-01。

## 输入数据

- 第 1 条：`logid = 80001`，`ai_requested_model = replay-model`，`ai_output_tokens = 200`。
- 第 2 条：第 1 条的克隆，唯一键字段不变，`ai_output_tokens` 改为 999（模拟上游重发且内容更新）。

## 操作步骤

1. 准备环境并启动 `log-reader`。
2. 写入第 1 条，等待表中出现该行且 `ai_output_tokens = 200`。
3. 写入第 2 条（同唯一键、改值），轮询等待该行 `ai_output_tokens = 999`。
4. 断言表行数仍为 1。
5. 停止 log-reader，原配置原日志目录重新启动（`-b` 从文件头补读）：文件内两条同键记录被再次重放。
6. 等待 3 秒（覆盖 FlushIntervalMs 200ms 的多个周期）后断言行数仍为 1，且 `ai_output_tokens = 999`（文件内最后一条胜出）。

## 预期结果

- 重发（步骤 3-4）：行数 = 1，`ai_output_tokens` 被覆盖为 999。
- `-b` 全量补读（步骤 5-6）：行数 = 1，值保持 999，无重复行、无写失败日志。

## 清理

停止 `log-reader` 进程，关闭数据库连接，DROP 测试专用数据库，删除临时目录。
