# TC-04-03 运行期断连自动重连

## 用例编号与名称

TC-04-03 运行期断连自动重连（`TestLR04_RuntimeDisconnectThenRecover`）

## 所属场景

LR04 MySQL 启动连接失败后台重试场景（scenario-LR04-mysql-startup-connect-retry）

## 版本声明

- `log-reader`：v1.5.0-dev 起（`mod_log_mysql` 二期改造：运行期断连自动重连，见 `doc/modifications/2026-09-30-mod-log-mysql-runtime-reconnect/design-changes.md`）

## 测试目的

验证运行期断连的自动恢复（二期行为）：

1. 已建连运行中 MySQL 挂掉：写路径在 `BatchTimeoutMs`（ExecContext ctx + 驱动 writeTimeout）约束的超时内失败，**不挂死**；
2. 写重试耗尽触发 `markDown`：`MYSQL_CONN_STATE` 转 `DOWN`、`MYSQL_CONN_LOST=1`，supervisor 后台重连，进程存活；
3. DOWN 期间到达的日志入队缓冲（`SENT_TO_MYSQL` 增长、`WRITE_BATCH_SIZE` 停滞），不丢；
4. MySQL 恢复后自动重连（`STATE=UP`），持有批优先补写 + 积压排空，**`SEND_MYSQL_FAILED=0`**——运行期断连不再线性丢批。

一期暂缓本用例的原因（连接池拨号无超时、断言窗口不稳定）已随二期写路径超时消除。

## 运行模式

单组件模式：真实 `log-reader` 进程 + testcontainers `mysql:8.0`（Docker `ContainerPause`/`ContainerUnpause` 模拟运行期断连/恢复）。外部 `LR_MYSQL_DSN` 后端无法 Pause，用例 skip。

## 前置条件

- 本机 Docker 可用；自动编译的 `log-reader` 二进制（缓存至 `tests/integration/.integration-test-bin/`）。

## 配置构造

- 与 TC-04-01 同模板，但 MySQL 先**不** Pause：正常建连后启动。
- 关键配置（`testdata/mod_log_mysql/mod_log_mysql.conf`）：`BatchTimeoutMs = 2000`（单批事务超时，决定 DOWN 出现的上界：`(MaxRetries+1) × (BatchTimeoutMs + 回退 + rollback 边界) ≈ 十余秒`，断言窗口 90s）；`ConnectTimeoutMs = 2000`（拨号超时）；`ConnectRetryIntervalMs = 200`。

## 输入数据

4 条 request 类型日志（`common.MakeRequestLog`），logid 41001–41004、模型互不相同：

| 阶段 | logid | 说明 |
|------|-------|------|
| 断连前 | 41001、41002 | 验证正常建连写入（基线） |
| 断连中 | 41003、41004 | 验证 DOWN 期缓冲 |

## 操作步骤

1. testcontainers 启动 MySQL → 建库 → 应用 DDL（MySQL 处于 UP 状态）。
2. 生成配置并启动 log-reader；`WaitMonitor` 断言 `STATE=UP`。
3. 写入 41001、41002；`WaitTableCount(2)`（正常路径落库）。
4. `MysqlEnv.Pause` 冻结容器（运行期断连）；写入 41003、41004。
5. `WaitMonitor` 断言 `STATE=DOWN`（90s 窗口）。
6. 断言 `SENT_TO_MYSQL=4`、`WRITE_BATCH_SIZE=2`（断连前行已落库，断连中行入队缓冲）；`waitExit(100ms)` 断言进程存活。
7. `MysqlEnv.Unpause` 恢复。
8. `WaitMonitor` 断言 `STATE=UP`（60s）；断言 `MYSQL_CONN_LOST=1`、`SEND_MYSQL_FAILED=0`。
9. `WaitTableCount(4)`；查询 `logid BETWEEN 41001 AND 41004` 的 distinct 计数 = 4。

## 预期结果

- 步骤 5：DOWN 在 BatchTimeoutMs 决定的有限窗口内出现（替代一期的"挂死无信号"）。
- 步骤 6：断连期全部 4 行入队、仅前 2 行落库，进程始终存活。
- 步骤 8-9：恢复后自动重连（`LOST=1`），持有批补写 + 积压排空，4 行齐全且 `SEND_MYSQL_FAILED=0`——与一期行为（每分钟约丢 30 批）形成对照。

## 清理

停止 log-reader（defer `stopReader()`），关闭日志生成器与数据库连接，终止容器并删除测试库，删除临时目录。

## 历史记录

- 一期（2026-09-29）因连接池拨号无超时暂缓，仅手工验证；
- 二期（2026-09-30，运行期断连自动重连）落地后自动化：`BatchTimeoutMs` 提供确定性断言窗口。
